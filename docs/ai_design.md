# CityPulse AI 设计说明

> 对应评分维度"AI 应用创新性 / AI 应用深度"的设计证据索引。

## 一、核心设计决策：预测模型与生成模型分工（反常规的克制）

行业常见做法是让大模型直接"猜城市"或输出趋势报告。CityPulse 把 LLM 从预测链路中**显式移出**：

| 环节 | 承担者 | 理由 |
|---|---|---|
| 会不会火（趋势排序） | 季节基线 + 加权基线 + 加速筛选（后续替换学习排序） | 可回测、可版本化、可解释；LLM 无法保证时间可审计性 |
| 解释为什么 | 因子分解 + 证据链汇总（来源/available_at） | 每个结论可回溯到原始证据，而非事后编故事 |
| 怎么行动（结构化草案） | **DeepSeek（唯一 LLM 入口）** | 生成是非确定性任务，正是 LLM 的优势区 |
| 审批与发布 | 人工（运营角色） | LLM 不进入任何写操作与事实字段 |

**这条边界是硬约束**：LLM 只接收服务端挑选的结构化字段（`citypulse/actions/deepseek.py`），输出必须通过 JSON Schema 校验；任一环节失败自动降级到确定性规则模板，并标记 `generator_type=rule_fallback`。

## 二、三分离输出与概率门禁（原创纪律）

演示行业普遍展示"爆发概率 xx%"。CityPulse 按设计规格把输出拆为**趋势分（排序分，非概率）、风险压力、证据完整度、行动优先级**四个独立量，并用代码级门禁禁止概率文案：

- `prediction/scoring.py`：趋势分是加权排序分，文档与页面均标注"非概率"；
- `calibration/`：Brier/ECE/可靠性分箱的校准实验工具已就绪，但样本 <100 判定 `insufficient_samples`，**概率展示保持关闭**直至管理员发布通过时间外验证的校准版本（`calibration/router.py` 的 `gate_note` 每次响应随行）。

## 三、轻量加速筛选（原创工作流）

`momentum_ratio`：近 3 日加权均值 / 窗口基线加权均值，≥1.15 标记"异常加速"。O(指标数) 的预筛在重排序之前先从 341 城目录筛出少数候选——"先筛后评"压缩预测周期；跨数据集版本的同日观测按最新提交去重，保证修订数据正确覆盖。

## 四、Agent / Prompt / 工作流设计（原文可查）

**系统 Prompt**（`citypulse/actions/deepseek.py`）：

```
你是文旅经营动作助手。只依据输入的城市信号与证据生成结构化动作草案，
不得编造无法由输入支持的事实。只输出 JSON。
```

**用户 Prompt 模板**：注入城市、趋势分、风险压力、证据完整度、行动优先级与因子 JSON，要求输出 `target_segment / campaign_theme / supply_actions / assumptions / risk_notes` 五字段，`response_format=json_object`，`temperature=0.2`。

**降级工作流**（任一步失败即回退规则模板，全程可观测）：

```
输入脱敏与长度限制 → 模板与模型版本绑定 → 超时(12s)与调用
→ JSON 解析 → Schema 校验（parse_payload）
→ 规则模板生成（high/medium/watch/blocked 四级，行动窗口按优先级错开）
→ 人工编辑（仅草稿态）→ 提交 → 运营审批 → 版本快照（generated/edited/submitted/approved）
→ 飞书群通知（可选 webhook）
```

规则模板本身也是设计产物：`high → 立即人工研判与备供`、`medium → 小范围验证`、`watch → 继续观察补证据`、`blocked → 仅风险处置`，并按命题洞察把目标客群锚定在 25 岁以下及大学生（00 后增量最快）。

## 五、鲁棒性证据

- 降级路径单测（超时/坏 JSON/字段缺失）×5；全站 110 后端 + 21 前端测试，CI 全绿
- DeepSeek 真实调用线上验证：延吉草案生成 → Schema 通过 → 运营批准，版本链完整
- 幂等/不可变：SHA-256 去重、数据集 commit 幂等、动作版本快照、预测失败不覆盖旧版本

## 六、飞书生态衔接

- **已实现**：动作方案批准后通过飞书自定义机器人 Webhook 推送群卡片（`CITYPULSE_FEISHU_WEBHOOK` 配置即用，见 README"飞书通知"）
- **规划中**（企业阶段）：动作草案同步为飞书多维表格行、审批走飞书审批流、告警进飞书群机器人；平台的三角色 RBAC 与飞书组织架构对齐
