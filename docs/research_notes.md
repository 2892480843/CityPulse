# CityPulse 研究笔记

## 1. 问题重定义

“下一座爆火小城”不是静态城市分类，而是一个带时间边界的排序问题：在日期 `t`，仅使用当时已经可获得的信息，对未来 7/14/30 天的异常旅行需求增长进行排序，并给出不确定性与可执行动作。

核心区分：

- **已火**：绝对热度已经很高，平台进入追赶阶段。
- **将火**：相对城市自身季节基线出现异常加速，但大众认知尚未完全形成。
- **可行动**：跨源证据充分、供给风险可控，值得上架、投放或备供。

## 2. 弱信号假设

| 假设 | 可观测代理变量 | 可能失效的情形 | 处理方式 |
|---|---|---|---|
| 内容传播会先于订单加速 | 内容量、互动增速、跨圈层扩散 | 单一大号或营销事件冲高 | 跨源确认、去异常账号、证据完整度 |
| 事件触发可形成短周期需求 | 演出、赛事、节庆、影视、政策 | 活动规模小、交通与住宿不足 | 加入可达性与供给承载约束 |
| 小城爆发往往是相对基线跃升 | 稳健 Z-score、变点、同比/环比 | 节假日季节性造成伪异常 | 城市自基线、同季节对照组 |
| 跨地域传播提高转化概率 | 外地内容占比、客源地扩散 | 讨论热但无旅行意图 | 引入搜索、路线和产品点击代理 |
| 风险压力决定动作强度 | 房价波动、库存、拥挤、负面舆情 | 供给数据缺失 | 双阈值、人工复核、观察池 |

## 3. 建模路线

1. 透明基线：加权评分 + 稳健 Z-score，先验证字段与业务闭环。
2. 异常检测：季节基线、变点检测、残差异常，识别“异常加速”。
3. 学习排序：LightGBM/XGBoost/LambdaMART，优化未来窗口 Top-K。
4. 概率校准：Platt 或 Isotonic，报告 Brier Score 与 ECE。
5. 证据解释：SHAP + 来源卡 + `available_at`，避免事后生成理由。
6. 动作生成：LLM 只读取结构化预测与证据，输出 JSON Action Plan。

## 4. 回测实验设计

- 正例：已知热点案例；对照：同区域、同季节、相似体量但未发生同等跃升的城市。
- 截点：`T0-30 / T0-14 / T0-7`，每个截点重新构造数据快照。
- 切分：严格时间前滚，不随机打散。
- 指标：Hit@5、NDCG@10、Lead Days、False Alerts、Brier/ECE、Evidence Coverage。
- 消融：去掉事件、内容、可达性、供给或风险特征，观察排序与误报变化。
- 基线：随机排序、绝对热度排序、仅内容增速、透明加权基线。

## 5. 当前材料与真实边界

现有候选城市、分数、排名和曲线均为模拟数据，用于证明数据合同、评分逻辑、界面和验证协议。正式结果须在合法数据接入后重新跑数，并输出数据版本、代码版本、截点和随机种子。

## 6. 下一步优先实验

1. 建立 30-50 城市、90-180 天的最小城市日期面板。
2. 完成 3 个正例 + 6-10 个对照城市的前滚回测。
3. 比较绝对热度、透明基线、变点检测与学习排序四种方案。
4. 量化“证据完整度”对误报率的影响。
5. 用模拟去哪儿搜索/订单特征做插拔测试，验证企业数据接入接口。
